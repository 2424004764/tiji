# 测试与发布

## 测试层级

- 单元：密码哈希、评分、状态机、token、schema 和分页。
- API：鉴权、越权、发布快照、重复提交、活动窗口和错误码。
- 前端：题库编辑、答题草稿、提交确认、错题收藏、语言切换。
- E2E：创建者发布活动 -> 访客答题 -> 创建者查看结果的完整链路。
- 兼容性：Chrome/Edge/Safari，移动与桌面 viewport，键盘和触控操作。

## 发布流程

1. Pull request 执行 lint、类型检查、单元和 API 测试。
2. Preview 环境执行 D1 migration 和 E2E，检查公开页面 meta、sitemap 和 noindex。
3. 生产先备份/确认 D1 migration，再发布 Worker 与两个前端入口。
4. 发布后检查健康接口、登录、公开活动和结果查询；观察错误率与延迟。

## 回滚

Worker 和前端保留上一版本可回滚；数据库迁移只采用向后兼容变更，禁止依赖不可逆回滚。若发现评分或数据问题，先暂停活动提交，再修复并通过快照复核。

## 观测

记录请求 ID、状态码、耗时、错误码和版本号；敏感数据脱敏。为 API 错误率、D1 错误、限流命中、提交失败和公开页 5xx 设置告警。
