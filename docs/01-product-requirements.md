# 产品需求

## 1. 目标

题迹让用户在低门槛下完成“创建题目、分享答题、查看反馈、重复练习”的闭环。创建者关注答题结果，答题者关注错题、收藏和历史记录。

## 2. 用户角色

- 创建者：注册并登录，维护题库，发布活动，查看自己活动的结果。
- 答题者：打开公开分享链接，输入活动内显示名，完成并提交答卷。
- 管理员：MVP 不开放独立后台，仅预留状态与审计字段。

## 3. MVP

### 必须有

- 用户名密码注册、登录、退出和当前会话
- 题库 CRUD、题目 CRUD、排序和发布前校验
- 单选、判断题，题干、选项、答案、解析、难度、标签
- 从题库创建答题活动；发布后生成不可枚举分享链接
- 访客输入显示名、开始答题、保存进度、提交答卷
- 创建者查看参与人数、完成率、平均分、题目正确率及答题者详情
- 登录用户的错题、收藏和答题记录
- zh-CN/en-US 文案切换及公开页面基础 SEO

### 不在 MVP

- 社交登录、付费、团队与复杂角色权限
- 图片/音频题、公式编辑器、AI 出题
- 实时协作答题、排行榜和公开结果链接
- 多端离线同步与小程序专属能力

## 4. 核心流程

1. 创建者注册/登录，创建题库并添加题目。
2. 创建活动，选择题库、配置标题、答题规则和时间窗口。
3. 发布活动，系统写入题目快照并返回分享 URL。
4. 答题者访问 URL，输入显示名，读取公开题目，不接收答案和解析。
5. 答题者提交；服务端基于快照评分并保证幂等。
6. 创建者在活动结果页查看汇总、答题者列表和每题表现。
7. 登录答题者在个人空间查看错题、收藏与记录。

## 5. 验收标准

- 未登录用户不能访问题库编辑和活动结果。
- 已发布活动的题目内容和评分依据不会因原题库编辑而改变。
- 分享接口不会返回答案、解析、内部 ID 或其他答卷内容。
- 同一个幂等键重复提交不会创建第二份有效答卷。
- 活动拥有者只能看到自己活动的结果。
- 公开页面可被搜索引擎抓取，拥有唯一 title、description、canonical 和 OG 信息。
- 桌面宽屏、平板和手机尺寸下，答题和管理流程均可完成。
